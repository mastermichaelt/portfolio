Portfolio as engineering system

This site is not a project grid — it is a navigable model of how projects, agents, workflows, governance, knowledge, skills, outputs, and articles reinforce each other.

MetaIAKnowledge

On this page

Problem Role System overview Key decisions Outcomes Evidence Related

Problem

Portfolios usually list projects as islands. Hiring managers cannot see judgment; engineers cannot see connective tissue. The interesting work is the system between the case studies.

Role

Information architect and prototypist — defined the graph, progressive disclosure patterns, and dual-speed UX (scan vs. deep dive).

System overview

Home for scanning, Projects for browsing, detail pages for evidence, Articles for narrative, System map for relationships, About for contact. Shared tokens and behaviors keep the experience coherent.

System overview · Portfolio as engineering system

Key engineering decisions

Decision 01
Graph over grid

System map is a first-class view, not an afterthought diagram.

Decision 02
Dual tempo

Scanner bar + deep sections so recruiters and engineers share one site.

Decision 03
Evidence packs

Collapse details by default; never invent metrics to look “impactful.”

Decision 04
Self-referential honesty

The portfolio is featured as a system — dogfooding the IA.

Outcomes

  • Visitors can enter from Home, Projects, or System without dead ends.
  • Each project page shares a stable section model for fair comparison.
  • Visual language (sage / warm neutrals) signals calm technical credibility.

No invented KPIs — outcomes are qualitative until you supply measured results.
