Platform · Case study

Editorial MCP

A Model Context Protocol surface where brand knowledge, skills, and review actions are tools with contracts — not chat folklore.

PlatformMCPKnowledgeSkills

On this page

Problem Role System overview Key decisions Outcomes Evidence Related

Problem

Editorial agents that “just know” the brand drift. Without tool contracts, retrieval and side effects hide inside prompts and cannot be reviewed or reused.

Role

Platform engineer for the MCP server shape: tool inventory, auth boundaries, knowledge store adapters, and skill packaging.

System overview

Tools cover read brand rules, search prior work, load a skill, draft under a schema, and open a review packet. Dangerous tools require elevated scopes. The editorial workflow is a client of these tools.

System overview · Editorial MCP

Key engineering decisions

Decision 01
Tools as policy

If it can change state or claim authority, it is a named tool with a schema.

Decision 02
Knowledge adapters

Brand docs and prior articles are queryable stores — not pasted context dumps.

Decision 03
Skill versioning

Skills are versioned artifacts with owners and deprecation paths.

Decision 04
Thin clients

Chat UIs and batch jobs share the same MCP server.

Outcomes

  • Agents become swappable; the contract stays stable.
  • Reviewers inspect tool traces instead of reconstructing intent from prose.
  • New editorial formats reuse skills without rewriting orchestration.

No invented KPIs — outcomes are qualitative until you supply measured results.
