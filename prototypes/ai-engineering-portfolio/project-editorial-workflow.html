AI-assisted editorial workflow

A production-minded drafting pipeline where retrieval, generation, and critique are separate stages — and humans approve anything irreversible.

WorkflowOutputsEvalHITL

On this page

Problem Role System overview Key decisions Outcomes Evidence Related

Problem

Editorial teams want AI speed without losing voice, brand, or accountability. Monolithic “write the article” prompts hide failure modes until publish time.

Role

Systems designer for the stage machine; defined interfaces between brief intake, knowledge retrieval, draft generation, critique, and publish readiness.

System overview

Each stage emits a typed artifact. Critique agents score clarity, brand fit, and claim support. Publish readiness is a checklist, not a vibes vote. Editorial MCP supplies tools; this workflow orchestrates them.

System overview · AI-assisted editorial workflow

Key engineering decisions

Decision 01
Stage contracts

Separate retrieve / draft / critique so regressions are attributable.

Decision 02
Human gates

No auto-publish. Critique can fail closed; humans reopen.

Decision 03
Claim support

Unsupported assertions become explicit TODOs instead of confident prose.

Decision 04
Reuse skills

Prompt skills live in the knowledge store — versioned, not copy-pasted.

Outcomes

  • Editors review structured packets (brief, sources, draft, critique) instead of raw chat logs.
  • Failures localize to a stage — retrieval miss vs. generation drift vs. weak critique.
  • Same workflow powers multiple output types without forking the orchestration.

No invented KPIs — outcomes are qualitative until you supply measured results.
